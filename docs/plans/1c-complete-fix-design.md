## 0. 文档目的

为 §1c 残留给出**可决策的修复设计空间分析**与**分阶段推荐路线**。残留的完整形态：

> store 读争用（复制期间外部读）→ 复制应用写路径延迟 → 排水数据间隙（随争用增长
> 无上界）→ 冻结误判 → 强制重连 → PSYNC 撞非命令边界（发散悖论）→ 降级 FULLRESYNC#2
> → 数据丢失（offset 收敛但数据不完整）。

## 2. 设计约束（已验证、不可违背）

- **C1** badger v4.9.6 读（`db.View`）写（`db.Update`）**共享 oracle/readTs**；读事务创建
  `readMark.Begin` + `txnMark.WaitForMark`（读创建等待在途写刷盘）；写提交 `hasConflict`
  冲突检测。
- **C2** `DetectConflicts=false` **否决**——keyLockMgr 覆盖不全（set/json/geo 等读改写依赖
  冲突检测保读改写安全）。
- **C3** 阈值调参路径定性失败（10s→30s→40s 全部部分/无效——间隙无上界）。
- **C4** **发散悖论**：从侧 offset 与主侧流边界的结构性不一致（七环节代码级全部精确 +
  运行期逐命令/ACK/应用历史三维度 0 异常——从侧视角不可见；完整定位需抓包级主从字节
  比对——超出当前工具范围）。
- **C5** 写路径对**任何额外扰动**极度敏感（读争用/写路径内日志 I/O 均扰动）——生产写
  路径须零额外开销（探针用后即清）。
- **C6** 恢复链路顺序已验：FULLRESYNC 流 = `ReadBulkString` → `LoadRDB`（含 FlushDB）→
  `readCommandLoop`——严格顺序、无加载/排水重叠。
- **C7** 幂等约束：ACK 落后补推会 double-apply 非幂等命令——**禁止**任何"重发已应用
  区间"的设计。
- **C8** 30s 阈值（`63b5c8c`）为已知最佳调参状态（2/15 部分缓解）；真冻结（40s 收敛窗内
  ≥30s 空闲）检测不受调参影响。

## 4. 设计目标与评价准则

| 目标 | 含义 |
|------|------|
| G1 触发消除 | 复制期间外部读不扰动（或扰动可控）复制应用写路径 |
| G2 误判稳健 | 停滞判定对无上界读争用间隙稳健（不因单点间隙越阈误判） |
| G3 丢失消除 | 即使误判重连发生，重连-恢复路径不丢数据（降级无损化） |
| G4 可验证 | 每项设计有 A/B 协议（沿用 dw_hist 协议）+ 守卫测试 |
| G5 兼容 | 不改坏幂等语义、冲突检测、快照一致性（C2/C6/C7） |

评价：每候选按 **杠杆**（对残留 2/15 的消除程度）× **风险**（回归面/损坏面）× **成本**
（实现+验证）三维评分，以推荐路线收口。

## 5. 候选方案分层对比

### 层 A：触发消除（读隔离 / 节流）——对应 G1

| 方案 | 描述 | 杠杆 | 风险 | 成本 | 判定 |
|------|------|------|------|------|------|
| **A1a 全局读并发闸** | 外部读路径（handler 层读命令入口）加并发信号量——限制同时存活的 `db.View` 数，降低 oracle/readTs 争用 | 中（直接降低争用源） | 中（读吞吐/延迟下降——所有读受影响；闸粒度需 A/B 定） | 中（读命令入口枚举 + 闸 + 配置化） | 候选（需权衡读 QoS） |
| **A1b 从侧角色读闸** | 仅 slave 角色启用读闸（主节点不受影响）——复制期间外部读被节流 | 中高（直击生产等价场景） | 低中（仅从侧读受限；从侧通常非读主源） | 低中（A1a + 角色开关） | **推荐候选**（生产语义最小） |
| A2 复制应用批量合并 | 排水/实时应用 N 条命令合并为单个 `db.Update`（减少 readTs 分配与冲突面） | 中（写侧减负） | **高**（WriteCommand 全部写命令 txn 化重构；读改写语义 + keyLockMgr 协调——回归面巨大） | 高 | 远期（阶段 3 评估） |
| A3 从侧免读调度 | 测试/部署把外部读调度到主侧（从侧不接读） | —（架构变通，非产品修复） | 低 | 低 | 变通（不治本） |
| A4 badger 读隔离 | 外部读走 managed mode（显式 readTs——不参与 oracle 分配）或独立读 oracle | 高（彻底解耦） | **极高**（badger 语义深改/替换——C1 约束下架构级；全部读写调用点波及） | 极高 | 远期架构项（阶段 3） |

### 层 B：误判链消除（停滞判定稳健化）——对应 G2

| 方案 | 描述 | 杠杆 | 风险 | 成本 | 判定 |
|------|------|------|------|------|------|
| **B1 双重确认** | 停滞判定需**连续 2 个 ACK 周期**（~2s）均"落后+空闲"才重连——单点瞬态（间隙尾部抖动）不触发。dw_armed1 捕获的 idle≈30.4s"刚越阈即误判"被消除 | 中（把误判从"间隙边界抖动"推到"连续 4s+ 间隙"——真冻结 40s+ 仍连续多周期触发——自愈延迟 +~2s 可容于 40s 收敛窗） | 低（reconnect.go 停滞分支小改 + 守卫更新） | 低 | **推荐候选**（低风险立即做——但与 40s 阈值同属"推阈"权衡——非根治——杠杆有限） |
| **B2 排水进度判据** | 判据从"纯 idle"改为"最近窗口内排水应用推进量 < 阈值"——读争用间隙中应用**仍在慢推进**（非停死）时不判冻结 | 中高（直击"读争用→慢→间隙"形态——只要推进就不误判；真冻结推进=0 仍判） | 中（"慢推进阈值"本身成调参对象——重蹈阈值脆弱 C3；需阶段 0 直方图数据定阈） | 中 | 阶段 2 候选（需观测数据支撑） |
| B3 主侧重确认 | 重连前向主侧确认"停滞为真" | **否决**（主侧视角连接健康/ACK 持续（实证）——无"未发完"概念——发送即写 socket——无从确认） | — | — | 否决 |

### 层 C：丢失消除（恢复路径重设计）——对应 G3

| 方案 | 描述 | 判定 |
|------|------|------|
| C1 降级前快照保全 | FULLRESYNC#2 前从侧先本地快照/备份——降级后校验失败可回滚 | 杠杆低（不消除丢失——只加回滚手段）+ 实现复杂——不推荐 |
| **C2 边界失败不降级**（续传兜底） | PSYNC offset 非边界时——主侧从"≤offset 的最近命令边界 B"重发 [B, mo)——从侧回退 B 重放 | **被 C4 阻塞**：发散悖论未解——回退区间 [B, offset) 可能与从侧已应用区间重叠 → double-apply 非幂等（C7 禁止）——发散根因未定前不可落地 |
| C3 降级排水对齐增强 | 降级后排水 [S2, mo) 的字节级对齐增强 | 交接链已验无缺陷（C6）；丢失与发散相关——发散未解前无可落地的字节级增强——阻塞同 C2 |
| C4 从侧命令级重放缓冲 | 从侧保留最近应用原始字节（环形）——重连时向主侧提议从侧视角的最近边界 | **否决**（同 C2 根因：从侧视角边界在主侧流可能非边界（悖论）——主侧重发区间不可信） |

**层 C 结论**：恢复路径重设计的可行前提是**发散根因消除（层 D）**——在 C4（发散悖论）未解前，
任何"基于字节边界语义的重放/回退"都不可靠。因此丢失消除的当前主线 = **减少误判触发**
（层 A/B）——让恢复路径（降级 FULLRESYNC）尽量不被触发。

### 层 D：发散消除（定位完成前提——工具范围外）

| 方案 | 描述 | 判定 |
|------|------|------|
| D1 抓包级主从字节比对 | 主侧发送字节 vs 从侧接收字节的直接比对（tcpdump/独立进程）——定位流级错位点 | 记录于 `f88187d`——超出当前工具范围——**需外部工具**——一旦定位发散根因，C2/C3 重新评估 |

## 6. 推荐路线（分阶段——按杠杆 × 风险 × 成本排序）

### 阶段 0：观测补全（先行——低成本高判别价值）

- 已落地：`retryMetrics.conflicts` 计数（`0a3317c`）。
- 补：写提交延迟直方图（>10ms 慢写分桶——INFO 暴露 + 服务端消费——实证慢写 415-463 条/批
  为争用固有）；停滞判定每次触发的 (armed, idle, masterOffset, slaveOffset) 周期计数。
- 目的：为 B1/B2/A1 的 A/B 提供判别数据（间隙分布 vs 冻结判定的重叠量化）。

### 阶段 1：低风险缓解（可立即做——守卫 + A/B 门槛验证）

1. **B1 双重确认**（停滞判定连续 2 个 ACK 周期确认）——reconnect.go 停滞分支小改；
   守卫更新（现有 4 守卫 + 新增"单周期瞬态不触发"负例）；dw A/B 门槛：2/15 → ≤1/15。
2. **A1b 从侧角色读闸**（slave 角色读并发闸——配置化默认关）——handler 读命令入口加
   闸 + 角色开关；A/B 验证读闸下的失败率归零。

### 阶段 2：若阶段 1 不足（中风险——需阶段 0 数据）

3. **B2 排水进度判据**——以阶段 0 直方图定"慢推进"阈值——替代/补充纯 idle 判据。

### 阶段 3：若仍残留（架构级——独立立项评估）

4. A2 批量应用 / A4 badger 读隔离——大改造独立立项；C1 降级前快照保全（若 G3 需兜底）。

### 并行（任何阶段）：层 D

5. **D1 抓包级定位**（外部工具）——发散根因一旦定位，C2/C3 恢复路径重设计重新评估
   （届时恢复路径设计可从"减少触发"升级为"降级无损化"）。

## 7. 验证协议（每方案门槛）

- **A/B 协议**（沿用 dw_hist1）：从侧 LLen 读探针（每 10 ACK）+ dw 回归 `-count=15` × 2 批
  （同主机同时段对照——规避 4/4 vs 6/6 的时段不确定性）——记录 PASS/FAIL/缺失/停滞/降级。
- **门槛**：方案生效需 A/B 失败 ≤ 1/15（对照 30s 基线 2/15）；纯对照（无读探针）不回归
  （0 失败 0 停滞）；守卫全绿；`--full` 1 次停滞+降级合计 < 2。
- **回归套件**：4 个停滞/冻结守卫 + 兼容三套（py/node/cli）+ tier-A PR-gate。

## 8. 风险与开放项

- **发散悖论未解（C4）**——阻塞恢复路径重设计（C2/C4）——当前可行主线 = 减少误判触发
  （层 A/B）；任何"基于字节边界语义的重放"在悖论未解前不可落地。
- **阈值脆弱性（C3）**——B1/B2 本质仍是"推阈/换判据"——可能重蹈 40s 覆辙——故每步以
  A/B 门槛验证（§7）收口，不无限调参。
- **观测缺口**——写路径延迟直方图服务端消费未做（阶段 0）；badger oracle 内部争用
  （读创建 readTs 等待 vs oracle 锁）机制仍未实证区分。
- **负载/时段不确定**——A/B 必须同主机同时段对照。
- **badger 升级/替换**（A4 依赖）——外部依赖决策（版本升级自带 oracled 争用变化）。
