# 2026-08-06 集群事故复盘：FLUSHDB 误清系统 key + 三节点同时重启脑裂

> 时间：2026-08-06 15:47–18:20（处置约 2.5 小时）
> 环境：10.1.2.16 三节点 BoltDB 集群（v8.51.3 → v8.52.x）
> 关联修复：`d82b2b4`（FLUSHDB 系统 key 保护）、`f250ad3`（WAL 截断）

## 事故一：FLUSHDB 把集群配置和复制身份一起清了

### 症状

部署验证时发现 node1 的 DBSIZE 从 709073 掉到 248266，且 key 全是 `{06S}` 格式（benchmark 写入被"规范化"后的样子）——排查后确认：**检查 FLUSHDB 命令支持时，`redis-cli FLUSHDB` 真的执行了清库**。

### 根因

`ClearAllData`（store 层）用全表遍历删除**所有** key，包括：
- `__REPL_META__:*`（replId、masterReplOffset、backlog）
- `cluster:config`（节点表、槽位分配、epoch）

Redis 的 FLUSHDB 只清用户数据、不清集群配置（集群配置在 `nodes.conf` 文件里）；BoltDB 把配置存 badger，被一起删了。后果（重启时暴露）：
- replId 丢失 → 重启生成新 ID → 从节点被迫 FULLRESYNC
- 集群配置丢失 → `LoadConfig` 失败 → **节点启动时认领全部 16383 槽**（`NewCluster` 的默认行为）

### 修复

`d82b2b4`：`collectAllKeys` 跳过系统 key（`__REPL_META__:` 前缀 + `cluster:config`）。线上验证：node3 FLUSHDB + 重启后 ID 与槽位保留。

## 事故二：三节点同时重启 → 脑裂

### 症状

一条 SSH 命令里连续 `systemctl restart boltdb-node1/2/3`。重启后：
- node1 认为自己是唯一 master（0-16383 全槽）
- node2 生成了新 ID（replId 被 FLUSHDB 清过），也认为 0-16383 是自己的
- node3 认为自己是 10923-16383 + 0-10922
- 三个节点各自为政，`CLUSTER NODES` 互相看不见（或把对方标 stale）

### 根因

1. **FLUSHDB 清了 `cluster:config`**（事故一），所有节点重启时 `LoadConfig` 都失败
2. `LoadConfig` 失败 → `NewCluster` 默认"当前节点负责所有槽位"（cluster.go）
3. **gossip 没有自动发现机制**：节点只向已知节点表（`cluster.Nodes`）发 PING，节点表也是从 config 加载的——配置没了，节点表空，谁也不知道谁
4. 三个节点**同时**重启放大了问题：正常滚动重启时（一个起来验证后再下一个），先起来的节点会通过 gossip 学习/被学习，而同时重启没有任何节点能"介绍"彼此

### 处置流程（约 30 分钟，已固化到 `scripts/cluster-ops.sh recover`）

```bash
# 1. 每个节点清掉内存里的全槽认领（RESET HARD 清槽位+节点表）
redis-cli -p 6337 CLUSTER RESET HARD   # node2/3 同样

# 2. 从 node1 发起 MEET（双向握手，gossip 传播让三节点互知）
redis-cli -p 6337 CLUSTER MEET 10.1.2.16 6338
redis-cli -p 6337 CLUSTER MEET 10.1.2.16 6339

# 3. 各自认领槽位（会 SaveConfig 持久化）
redis-cli -p 6337 CLUSTER ADDSLOTSRANGE 0 5460
redis-cli -p 6338 CLUSTER ADDSLOTSRANGE 5461 10922
redis-cli -p 6339 CLUSTER ADDSLOTSRANGE 10923 16383

# 4. 验证三节点视角一致
redis-cli -p 6337 CLUSTER INFO   # slots_assigned:16384
```

### 相关边界（P3 usurp 逻辑的配合）

旧节点 ID 失联后会被其他节点标记 FAIL 并**接管其槽位**（`usurpedSlots`，P3 修复）。恢复时必须：
1. 接管方先 `CLUSTER DELSLOTS <接管范围>` 释放
2. `CLUSTER FORGET <旧ID>` 移除幽灵节点
3. 新节点（若重建了数据目录，ID 会变）重新 `MEET` + `ADDSLOTS`
