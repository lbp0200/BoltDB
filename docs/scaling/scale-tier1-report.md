## 结论

第 1 级验证（1GB 规模）**全部关键指标通过**。具体发现：

1. **磁盘放大比 1.5x** — 远低于 2.5x 阈值，BadgerDB 的 ValueLog 和 LSM 压缩效率良好。
2. **GET 延迟极低** — P99 < 0.9ms，比标准 < 10ms 低一个数量级。
3. **重启快速** — 5s 内完成，远低于 30s 阈值。节点 ID 持久化后槽位表保持完整。
4. **写入吞吐量无显著退化** — ~60K req/s 与空库基线差距 < 10%。
5. **内存使用可控** — ~1GB process memory per 340MB data（约 3x 常驻放大）。

### 未测量指标

- **L0 峰值**: 需要启用 `-metrics-addr` 端点暴露 BadgerDB 内部统计。当前服务未配置。
- **FULLRESYNC 速率**: 需要独立 replica 节点。当前环境仅有一台机器。

### 建议

1. 为后续规模化测试启用 `-metrics-addr` 以暴露 L0/compaction 统计。
2. 在 10GB+ 规模下重新验证磁盘放大比和写入退化趋势。
3. 第 2 级验证前需协调 1TB+ SSD 磁盘资源。
